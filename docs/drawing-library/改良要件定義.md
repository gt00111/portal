# 図面ライブラリ改良 要件定義書

本書は、板金製造支援システム（曲げ支援）が図面ライブラリを「部品（品番）単位」で参照するために必要な、図面ライブラリ側の改良要件を定義する。板金製造支援システム仕様書 `00_プロジェクト概要.md` §10 で「別途整理」とされた内容に対応する。

---

# 1. 背景

## 1.1 曲げ支援からの要求

板金製造支援システムは **品番中心設計**（`03_システムコンセプト.md`）を採る。現場・設計者は品番を起点に、その品番の最新版図面（PDF）を検索・表示できる必要がある（ロードマップ Phase 1 完了条件）。

図面 PDF・図番・品番・Rev の正本は **図面ライブラリ**（`drawing-library.db`）であり、板金製造支援システムはこれを **参照のみ** で利用する（STD-002 / STD-008、`09_データアーキテクチャ設計.md` TBL-001）。

## 1.2 仕様書の前提と実装実態の乖離（重要）

| 観点 | 仕様書の記述（`00`§10, `02`§9） | 実装の現状（コード確認） |
|---|---|---|
| 自社発行図面の管理単位 | 「トップアセンブリ単位でPDFを結合して管理。部品単位で取得・表示できない」 | `drawings` テーブルは `product_name`（図面番号＝品番）＋ `revision` 単位で 1 レコード＝1 PDF を登録可能。カスケード（客先→機種→図面番号）・現行版判定（`is_current`）・Rev 履歴を実装済み |

すなわち、**スキーマ上は既に品番単位の管理が可能**であり、仕様書が懸念した「結合PDF問題」は**登録運用（実データの入れ方）に起因する可能性が高い**。

したがって本改良は、まず **実データの登録粒度を確認（REQ-DL-001）** し、その結果に応じて改良範囲を確定する **段階的アプローチ** を採用する。

---

# 2. 改良方針

```text
REQ-DL-001（実データ確認）
        │
        ├─ 品番単位で登録済み ──▶ REQ-DL-002（参照API整備）＋ REQ-DL-003（品質担保）のみで足りる（小規模）
        │
        └─ 結合PDF運用が残存 ──▶ 上記に加え REQ-DL-004（部品単位登録への移行）が必要（中規模）
```

- 全面改修は行わない。曲げ支援 Phase 1 に必要な最小限に絞る。
- 図面ライブラリの既存機能（顧客図面タブ・PDF比較タブ・自社発行 CRUD）には破壊的変更を加えない。
- 他システムのデータを書き換えない（STD-008）。板金製造支援システムからは**読み取り専用**で参照する。

---

# 3. 改良要件

## 3.1 REQ-DL-001 実データの登録粒度確認（最優先・調査）

**目的:** 現行の自社発行図面（`drawing_type = 'work'`）が、部品（品番）単位で登録されているか、トップアセンブリ結合PDFで登録されているかを確認する。

**確認項目:**
- `product_name`（図面番号＝品番）が部品単位で一意に登録されているか
- 1 レコードの PDF が単一部品図か、複数部品を結合したアセンブリ図か
- 同一品番に複数 Rev がある場合、現行版が正しく判定されているか

**確認方法（例）:** `drawing-library.db` の `drawings` テーブルを対象に、`drawing_type='work'` の行を `customer_name` / `model` / `product_name` / `revision` 別に集計し、実ファイル（PDF）の中身を抜き取り確認する。

**成果物:** 確認結果メモ（本書 §7 に追記）。この結果で REQ-DL-004 の要否を確定する。

## 3.2 REQ-DL-002 品番参照API（read-only）の整備【必須】

**目的:** 板金製造支援システムが「品番 → 最新版図面」を安全に参照できる公開 API を図面ライブラリ側に用意する。

**要件:**
- 入力: 品番（`part_number`）。必要に応じて客先・機種で絞り込み。
- 出力: 最新版（現行版）の `drawing_id` / 図番 / Rev / PDF 相対パス / 更新日時。
- 対象は自社発行（`drawing_type = 'work'`）、`is_obsolete = 1` は除外。現行 Rev 選定は既存 `drawingRevisionSort.ts` のロジックを流用する。
- PDF バイナリ取得は既存の読取経路（`drawing:readFile` 相当、相対パス→base64、パストラバーサル防止）を再利用する。
- **板金製造支援システムはこの API 経由でのみ参照し、`drawing-library.db` へ直接書き込まない**（STD-008）。
- モジュール間の直接 import は禁止（`.cursor/rules`）。参照は共有 DB コネクション経由の read-only Repository（板金支援側 `drawing-ref.repo.ts`）または図面ライブラリが公開する read-only 関数として実現する。実装方式は設計フェーズで確定する。

**API 仕様（案）:** 詳細は板金支援側 `15_IPCチャンネル定義.md` の `smsupport:searchParts` / `smsupport:getDrawing` に定義する。図面ライブラリ側に新規 IPC を増やすか、板金支援 Repository が DB を直接読むかは設計時に決定する（いずれも read-only）。

**確定方式（2026-07-09）:** 板金支援モジュールの `drawing-ref.repo.ts` が、共有 DB 接続レイヤ `@main/db/drawingLibraryConnection.ts`（`getDrawingLibraryDb()` / `getDrawingLibraryDataDir()`）経由で `drawing-library.db` を **読み取り専用** 参照する方式を採用。現行版 Rev 選定は `@shared/drawingRevisionSort.ts` を再利用。図面ライブラリ**モジュール**（`src/main/modules/drawing-library/`）は import せず（モジュール間直接依存の禁止に準拠）、DB 接続レイヤと `@shared` のみを利用する。図面ライブラリ側への新規 IPC 追加は不要だった。

## 3.3 REQ-DL-003 データ品質の担保【必須】

**目的:** 「1 品番 = 最新版 1 図面」を安定して取得できるようにする。

**要件:**
- 同一「客先＋機種＋図番（品番）」グループ内で現行版が一意に決まること（既存 `is_current` ロジックで担保）。
- Rev アップは新規登録として扱う既存運用を維持し、ヘルプ・登録ガイドで明確化する。
- 必要に応じ、自社発行登録時に品番・Rev の必須チェックを軽く追加する（過剰なバリデーションは避ける）。

## 3.4 REQ-DL-004 部品単位登録への移行【必須・実施決定 2026-07-09】

**背景（利用者ヒアリングで判明）:** 実運用では、製品を構成する部品図面PDFを**1ファイルに結合してトップアセンブリ単位で登録**しており、個々の部品図面を検索できない。REQ-DL-001 のテストデータ（2件）はこの実運用を反映していなかった。したがって本要件は **実施決定**。

**目的:** 自社発行図面を **部品（品番）単位** で登録・検索・取得できるようにする。曲げ支援が部品品番で最新版図面を参照できることを担保する。

### 3.4.1 データモデル

- **1部品PDF ＝ 1 `drawings` 行**（結合PDF＝1行を廃止）。
- 列追加 **`assembly_number`**（トップアセンブリ品番）。`product_name` は **個々の部品品番** を保持。
- グループキー：`(customer_name, model, assembly_number, product_name)`。現行版判定はこのキー内で最大 Rev を採用（`drawingRevisionSort.ts` を拡張）。

### 3.4.2 登録フロー（複数選択・差分Rev）

- 登録フォーム（客先／機種／**アセンブリ品番**／Rev）は現行UIを踏襲。「図番／品番」欄は **アセンブリ品番** の意味に変更。
- PDF 取り込みを **複数選択** に対応（`drawing:pickPdf` を配列返却化）。
- **各PDFファイル名＝部品品番**として自動取得（取込後に一覧で修正可）。
- **スナップショットRev運用（2026-07-10 更新）:** 新Revでは**変更のあった部品PDFのみ**取り込めばよいが、内部では**前Revの現行部品一式を新Revフォルダにコピー継承**し、今回取り込んだPDFで同一部品を上書き・新規部品を追加する。結果として**各Revフォルダは常にアセンブリの完全なスナップショット**となり、任意のRevを部品一式で閲覧・Rev切替できる。

  ```text
  Rev A: p1,p2,p3 取込 → RevAフォルダ = { p1,p2,p3 }
  Rev B: p2 のみ取込   → RevBフォルダ = { p1(継承),p2(新),p3(継承) }
  ```

  - 登録フォームは、SKU 選択時（または「前リビジョンの部品を読込」）に**前Revの現行部品を一覧に読み込む**。継承部品は実ファイルを新Revフォルダに**物理コピー**する（`carryFromRelativePath` 経由）。
  - 一覧から**不要になった部品を行削除**でき、削除した部品は新Revには含まれない（＝Revごとに部品構成の増減が可能）。
  - 新規PDF取込時に同一品番があれば上書き確認ダイアログを表示。
  - 同一Revの再登録時は、そのRevの既存行/ファイルを削除して作り直す（上書き）。
  - 送信された一覧がそのまま新Revの完全スナップショットになるため、Rev履歴・Rev切替で過去Revの部品一式を確実に参照できる（当初の差分方式では未変更部品の過去Rev行が生成されず履歴が追えない問題があったため変更）。
  - 詳細画面内の部品削除は、ホームに戻らず詳細に留まって一覧を再取得する。

### 3.4.3 保存フォルダ

- `drawings/mycompany/<客先>/<機種>/<アセンブリ品番>/<Rev>/<部品品番>.pdf`
- 既存の `drawings/mycompany/<客先>/` 直下運用は互換のため読み取り可能なまま残す。

### 3.4.4 表示（自社発行タブ）

- 一覧は現行どおり**アセンブリ単位**で表示。
- 詳細は **両方式** を提供：(a) 裏で部品PDFを結合して1つの連続PDFとして表示、(b) 部品をリスト/タブで選び1ファイルずつ表示。結合は `pdf-lib`（既存依存）で都度生成し、結合ファイルは保存しない。

### 3.4.5 既存データ

- テスト段階でデータがほぼ無いため **移行は行わない・併存**。今後の登録から部品単位とする。

### 3.4.6 影響範囲

- `drawingLibrarySchema.ts`（`assembly_number` 追加・既存DBは `ALTER TABLE`）
- `drawings.repo.ts`（複数登録・`assembly_number`・現行版判定拡張・アセンブリ単位一覧）
- `drawingStorage.ts`（保存先の階層化）
- `drawing:pickPdf` / `drawing-library.handler.ts`（複数選択）
- `DrawingDbTab.tsx`（複数選択取込UI・詳細の結合/切替表示）
- 曲げ支援 `drawing-ref.repo.ts`（`product_name`＝部品品番前提。グループキーに `assembly_number` を加味）
- 非対象：顧客図面タブ・PDF比較タブ
