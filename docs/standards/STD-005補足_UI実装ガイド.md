# STD-005 補足：UI実装ガイド

本書は `STD-005_現場中心UI,UX設計標準.md` を **実装レベルに具体化** した補足ガイドである。STD-005 は原則・配置ルールを定めるが、デザイントークンの具体値・共通コンポーネントの実装・アクセシビリティ基準が未定義のため、これを補う。板金製造支援システム（曲げ支援）から初適用し、以後の全サブアプリで共通利用する。

> 本ガイドは既存のデザイン基盤（`tailwind.config.ts` の CSS 変数トークン、`src/renderer/src/components/ui/`）を正とし、新規に別系統のトークンを作らない。

---

# 1. デザイントークン（既存基盤への対応）

STD-005 のセマンティックカラー（§6）を、既存の Tailwind トークンにマッピングする。**新規の色を発明しない。**

## 1.1 セマンティックカラー対応表

| STD-005 の意味 | 用途 | Tailwind トークン | CSS 変数 |
|---|---|---|---|
| 青（通常情報） | 一般表示・主要操作・リンク | `accent-primary` | `--color-accent-primary` |
| 緑（正常・完了） | 成功・完了状態 | `state-success` | `--color-state-success` |
| 黄（注意） | 警告・要確認 | `state-warning` | `--color-state-warning` |
| 赤（エラー・危険） | エラー・削除 | `state-danger` | `--color-state-danger` |

**必須ルール（STD-005 §6）:** 色だけで状態を判断させず、**必ず文字（ラベル）も併記** する。例：`● 加工可` / `▲ 要確認` / `× 加工不可`。

## 1.2 面・文字・境界

| 役割 | トークン |
|---|---|
| 背景（ベース／面／浮き） | `bg-base` / `bg-surface` / `bg-elevated` |
| 文字（主／副／薄） | `fg-primary` / `fg-muted` / `fg-subtle` |
| 境界 | `border-subtle` / `border-strong` |
| 角丸 | `rounded-sm/md/lg`（`--radius` 基準） |

## 1.3 タイポグラフィ

- フォント: `font-sans`（Inter + Noto Sans JP）。
- **現場優先で本文は小さくしすぎない**（`text-sm` 以上を基本、重要情報は `text-base`〜`text-lg`）。
- 情報の優先順位（STD-005 §3.2）はフォントサイズと配置で表現する。曲げ支援では **PDF図面が最大** となるようレイアウト比率で担保する。

## 1.4 余白・密度

- 現場はタッチ／遠目の視認もあり得るため、**操作要素は詰めすぎない**。ボタンは既存 `Button` の `md`（高さ 40px）以上を基本、主要操作は `lg`。
- カード・パネル間は一定の余白（`gap-4` 目安）を確保する。

# 2. 共通コンポーネント

STD-005 §7 の共通 UI 部品を、既存 `src/renderer/src/components/ui/` にマッピングする。**既存があるものは新規作成しない。**

| STD-005 部品 | 既存コンポーネント | 状態 |
|---|---|---|
| SearchBox | （`TextField` + カスケード `Select` を組合せ） | 既存流用。曲げ支援で `PartSearchBox` として組成 |
| Table | `DataTable` | 既存流用 |
| Card | `Card` | 既存流用 |
| Panel | （`Card` ベースで構成） | 既存流用 |
| Dialog | `Modal` | 既存流用 |
| Toolbar | （`Button` 群を配置） | 既存流用 |
| Toast（通知） | `Toast` / `useToast` | 既存流用 |

## 2.1 命名（STD-003 整合）

サブアプリ固有の複合コンポーネントは役割を明確にした名前を付ける：

```text
PartSearchPage        # ページ
PartSearchBox         # 品番検索の入口
DrawingPanel          # PDF図面パネル（最大表示）
ProcessConditionCard  # 加工条件カード
TechnicalNotePanel    # 技術ノート
ProcessHistoryTable   # 加工履歴一覧
```

## 2.2 状態表示コンポーネント（新規・要検討）

判断結果や加工可否（OK/注意/NG）を「色＋文字」で示す共通バッジが必要。既存 `state-*` トークンを用いた `StatusBadge` を共通化することを推奨（各アプリで重複実装しない）。

# 3. レイアウト規約（STD-005 §4.3 の実装）

ボタン配置を全画面で統一する。共通レイアウトで強制することを推奨。

| ボタン | 配置 | variant |
|---|---|---|
| 保存 | 画面右下 | `primary`（青） |
| 戻る | 画面左上 | `ghost` / `secondary` |
| 検索 | 画面上部 | `primary` |
| 削除 | 右上（警告色） | `danger`（赤）＋確認ダイアログ必須 |

- 破壊的操作（削除）は必ず `Modal` による確認を挟む（STD-005「間違えにくい」）。
- 画面遷移は `検索 → 一覧 → 詳細 → （編集）→ 保存 → 一覧へ戻る` の統一フロー。不要な遷移を作らない。

# 4. 曲げ支援 SCR-001 の適用例

`08_画面要件.md` の部品詳細レイアウトを本ガイドで具体化する。

```text
┌──────────────────────────────────────────┐
│ [← 戻る]            部品詳細：<品番>          │  ← 戻るは左上
├──────────────────────────────────────────┤
│                                          │
│            DrawingPanel（PDF最大表示）      │  ← 最優先・最大
│                                          │
├──────────────────────────────────────────┤
│ [ 部品詳細 | シミュレーション | 技術ノート ]  │  ← タブで情報分割（Progressive Disclosure）
│  選択タブの内容（加工条件カード等）           │
└──────────────────────────────────────────┘
```

- 設計者・現場で画面を分けない（STD-005 §8）。編集可否は権限（`editor`）で切り替える。
- Phase 1 では「部品詳細」タブに図面メタのみ表示。加工条件・技術ノート・履歴は Phase 2 で追加（未実装タブは非表示または「準備中」表示）。

# 5. アクセシビリティ最低基準（STD-005 の補完）

STD-005 は「色＋文字」の併記のみ規定。現場利用に必要な最低基準を以下に補う。

- **フォーカス可視化**: 既存 `Button` の `focus-visible:ring` を踏襲。全操作要素でフォーカスリングを消さない。
- **キーボード操作**: 検索・一覧・詳細の主要操作は Tab / Enter で完結できること。
- **十分なコントラスト**: 文字は `fg-primary`／`fg-muted` を基本とし、`fg-subtle` を本文に使わない。
- **状態の多重表現**: 色 + アイコン + テキストの 3 点で状態を示す（色覚特性に配慮）。
- **クリック領域**: 主要操作は高さ 40px 以上（`Button` md 以上）。
