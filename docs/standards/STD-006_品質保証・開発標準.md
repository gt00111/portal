# 1. 目的

本標準は、ポータルを構成するすべてのサブシステムにおいて、一定以上の品質を維持しながら継続的に開発・保守を行うための共通ルールを定義する。

AIを活用した開発環境においても、最終的な品質は人が保証することを基本原則とする。

---

# 2. 基本方針

ポータルでは以下の品質方針を採用する。

- 品質を優先し、開発速度のみを追求しない。
    
- AIは開発支援ツールとして利用する。
    
- 最終判断・最終責任は開発者が持つ。
    
- 標準設計書（STD）に従って実装する。
    
- レビュー・テスト・ドキュメント更新を必須とする。
    

---

# 3. 品質保証の考え方

品質保証は以下の流れで実施する。

```text
要件定義

↓

設計

↓

実装

↓

レビュー

↓

テスト

↓

ドキュメント更新

↓

リリース
```

「動くこと」を完成条件とはしない。

---

# 4. レイヤーごとの責務確認

## UI

担当

- 表示
    
- 入力
    
- 状態管理
    

禁止事項

- SQL実行
    
- 業務判断
    
- Repository呼び出し
    

---

## Handler

担当

- IPC受付
    
- 入力チェック
    
- Service呼び出し
    

禁止事項

- SQL実行
    
- 業務ロジック
    
- 判断処理
    

---

## Service

担当

- 業務ロジック
    
- トランザクション
    
- システム間連携
    
- 判断エンジン呼び出し
    

禁止事項

- SQL実行
    
- UI制御
    

---

## Repository

担当

- CRUD
    
- SQL実行
    
- データ取得
    

禁止事項

- 業務ロジック
    
- 判断処理
    
- UI制御
    

---

# 5. AI利用方針

AIは以下の用途で利用する。

- コード生成
    
- リファクタリング提案
    
- ドキュメント作成支援
    
- テストコード作成支援
    
- コードレビュー補助
    

AIが生成したコードは、そのまま採用しない。

必ず人が内容を理解し、レビューを行う。

---

# 6. コードレビュー

すべての実装はレビューを実施する。

レビューでは以下を確認する。

- 命名規則
    
- 責務分離
    
- アーキテクチャ準拠
    
- 例外処理
    
- コメント
    
- 可読性
    
- パフォーマンス
    
- 保守性
    

標準設計書（STD）に違反する実装は修正対象とする。

---

# 7. テスト方針

各機能は最低限以下を確認する。

- 正常系
    
- 異常系
    
- 境界値
    
- エラー処理
    

重大な機能追加・修正時は、既存機能への影響も確認する。

---

# 8. Git運用

基本ブランチ構成は以下とする。

```text
main

↑

develop

```

運用ルール

- 開発は develop ブランチで行う。
    
- develop 完了後、mainへマージする。
    
- リリース時はmainにする。
    
- mainへの直接コミットは禁止する。
    

---

# 9. Definition of Done（完了条件）

機能が完成したと判断するためには、以下をすべて満たすこと。

- 要件を満たしている。
    
- コードレビュー完了。
    
- テスト完了。
    
- エラーが解消されている。
    
- ドキュメント更新済み。
    
- 必要に応じてDB更新済み。
    
- AI生成コードを人が確認済み。
    

「画面が動く」だけでは完成としない。

---

# 10. ドキュメント更新

設計変更・機能追加時は、関連ドキュメントを更新する。

対象例

- 要件定義
    
- 標準設計書（STD）
    
- ER図
    
- データ辞書
    
- README
    

実装とドキュメントの内容は常に一致させる。

---

# 11. 品質改善

品質は一度決めて終わりではない。

運用を通じて改善を続ける。

改善対象

- コード品質
    
- UI/UX
    
- パフォーマンス
    
- 保守性
    
- 開発効率
    
- AI活用方法
    

改善内容は必要に応じて標準設計書へ反映する。

---

# 12. 設計原則

本ポータルでは、

**「品質は後から作るものではなく、最初から設計するもの」**

という考え方を採用する。

また、

**「AIがコードを書く時代だからこそ、人が品質を保証する」**

ことを開発の基本原則とする。

すべての開発者は、本標準を遵守し、長期的に保守しやすく、安心して成長できる製造プラットフォームを構築することを目指す。
