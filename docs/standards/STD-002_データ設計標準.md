# 1. 目的

本標準は、ポータルを構成するすべてのシステムに共通するデータ設計ルールを定義する。

データの重複管理を防ぎ、保守性・拡張性・システム間連携を容易にすることを目的とする。

---

# 2. 基本方針

ポータルでは以下の基本方針を採用する。

- データは重複管理しない。
    
- データごとに正本（Single Source of Truth）を定める。
    
- 他システムのデータは参照のみとする。
    
- 共通データは共通マスタで管理する。
    
- システム固有データのみ各サブシステムで保持する。
    

---

# 3. データ責務

各データは責任を持つシステムを一つだけ定める。

|データ|正本|
|---|---|
|案件|生産ボード|
|客先図面|図面ライブラリ|
|自社図面|図面ライブラリ|
|Rev情報|図面ライブラリ|
|BOM|資材管理|
|部品構成|資材管理|
|客先|master.db|
|機種|master.db|
|ユーザー|master.db|
|機械|master.db|
|金型|master.db|
|加工条件|板金製造支援システム|
|加工履歴|板金製造支援システム|
|技術ノート|板金製造支援システム|

他システムは正本データを直接保持せず、Repository経由で取得する。

---

# 4. データ共有原則

システム間のデータ共有は以下を原則とする。

```text
正本DB
    │
Repository
    │
利用システム
```

他システムのテーブルへ直接アクセスする設計は禁止する。

---

# 5. データ識別子

ポータル全体で使用する主要識別子を統一する。

|項目|物理名|
|---|---|
|案件ID|project_id|
|品番|part_number|
|図面ID|drawing_id|
|客先ID|customer_id|
|機種ID|model_id|
|ユーザーID|user_id|
|機械ID|machine_id|
|金型ID|tool_id|
|Rev|revision|

同一意味のデータに複数の物理名を使用しない。

---

# 6. 共通カラム

すべてのテーブルで可能な限り以下の共通カラムを採用する。

|カラム|説明|
|---|---|
|id|主キー|
|created_at|作成日時|
|updated_at|更新日時|
|created_by|作成者|
|updated_by|更新者|
|is_active|有効フラグ|

論理削除を採用する場合は `is_active` を利用する。

---

# 7. データライフサイクル

データは以下の流れで管理する。

```text
作成

↓

更新

↓

履歴管理

↓

無効化
```

原則として物理削除は行わず、履歴を保持する。

---

# 8. データ品質

データ品質を維持するため、以下を遵守する。

- 必須項目は必ず入力する。
    
- 同一データを複数登録しない。
    
- 正本データ以外は編集しない。
    
- 更新履歴を保持する。
    
- データ整合性を維持する。
    

---

# 9. 将来拡張

新しいサブシステムを追加する場合も、本標準を適用する。

新規データは、

1. 正本システムを決定する。
    
2. データ責務を定義する。
    
3. 共通命名規則に従う。
    
4. Repository経由で公開する。
    

この手順を必ず実施する。

---

# 10. 設計原則

本標準では、

「データは会社の資産である」

という考え方を採用する。

システムのためにデータを持つのではなく、

会社全体で活用できる資産として管理する。

すべてのシステムは、この考え方を前提として設計・実装する。
