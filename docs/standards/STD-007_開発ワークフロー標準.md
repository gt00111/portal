# 1. 目的

本標準は、ポータルを構成するすべてのシステムを、一定の品質・設計思想・開発手順で継続的に開発するための共通ワークフローを定義する。

本標準は単なる開発手順ではなく、ポータル開発チームの共通文化として位置付ける。

---

# 2. 基本方針

ポータル開発では以下の考え方を採用する。

- 要件を明確にしてから実装する。
    
- 設計を理解してからコードを書く。
    
- 分からないことは質問して確認する。
    
- AIは開発を支援するツールであり、設計を決定するものではない。
    
- 実装よりも設計品質を優先する。
    
- 開発と同じくらいドキュメント更新を重視する。
    

---

# 3. 標準開発フロー

ポータル開発は以下の流れで進める。

**FLOW-001 標準開発フロー**

```text
課題・要望

      │

      ▼

要件整理

      │

      ▼

要件定義

      │

      ▼

質問・確認

      │

      ▼

設計

      │

      ▼

AI実装

      │

      ▼

レビュー

      │

      ▼

修正

      │

      ▼

テスト

      │

      ▼

ドキュメント更新

      │

      ▼

リリース
```

各工程を省略してはならない。

---

# 4. 要件定義

実装を開始する前に、必ず要件定義を作成する。

要件定義では以下を明確にする。

- 目的
    
- 対象業務
    
- 画面
    
- データ
    
- 処理
    
- 制約条件
    
- 完了条件
    

要件が曖昧な状態で実装を開始しない。

---

# 5. 設計

要件定義を基に設計を行う。

設計では以下を整理する。

- データ構造
    
- モジュール構成
    
- レイヤー構成
    
- UI構成
    
- データフロー
    
- エラー処理
    
- 他システムとの連携
    

設計完了後に実装へ進む。

---

# 6. AI活用方針

AIは開発支援ツールとして活用する。

主な用途

- コード生成
    
- リファクタリング
    
- ドキュメント作成
    
- テストコード作成
    
- レビュー支援
    

AIへ依頼する際は、十分な情報を事前に準備する。

例

- 要件定義
    
- 標準設計書（STD）
    
- 画面要件
    
- ER図
    
- データ辞書
    

情報が不足した状態で実装を依頼しない。

---

# 7. AIツールの役割

各AIツールの役割を明確にする。

|ツール|主な役割|
|---|---|
|ChatGPT|要件整理・設計・レビュー・改善提案|
|Codex|実装・コード生成・リファクタリング|
|Cursor|実装補助・修正・デバッグ・プロジェクト編集|

役割を分担することで、それぞれの強みを活かした開発を行う。

---

# 8. 質問する文化

ポータル開発では「質問すること」を重要な文化とする。

分からないことや判断に迷うことがあれば、必ず確認を行う。

質問を通じて、

- 要件の明確化
    
- 設計品質の向上
    
- 手戻りの削減
    

を実現する。

質問は設計品質を高めるための重要な工程であり、省略してはならない。

---

# 9. レビュー

実装後は必ずレビューを行う。

レビュー項目

- 要件との整合性
    
- 標準設計書（STD）準拠
    
- 命名規則
    
- 責務分離
    
- 可読性
    
- 保守性
    
- UI/UX
    

レビュー完了後に修正・改善を行う。

---

# 10. テスト

レビュー完了後、テストを実施する。

確認項目

- 正常系
    
- 異常系
    
- 境界値
    
- 既存機能への影響
    

問題があれば修正し、再テストを行う。

---

# 11. ドキュメント更新

実装内容に変更があった場合は、関連ドキュメントを更新する。

対象

- 要件定義
    
- 標準設計書（STD）
    
- README
    
- ER図
    
- データ辞書
    

コードとドキュメントは常に一致した状態を維持する。

---

# 12. 継続的改善

開発プロセスも継続的に改善する。

改善対象

- 開発フロー
    
- AI活用方法
    
- 標準設計書
    
- レビュー手順
    
- テスト手順
    

改善内容は標準設計書へ反映し、チーム全体で共有する。

---

# 13. 開発文化

ポータル開発では、以下の価値観を共有する。

- 要件を理解してから実装する。
    
- 設計を理解してからコードを書く。
    
- 分からないことは質問する。
    
- AIを積極的に活用する。
    
- 最終品質は人が保証する。
    
- ドキュメントを資産として育てる。
    
- システムだけでなく、開発プロセスも継続的に改善する。
    

---

# 14. 設計原則

本ポータルでは、

**「設計が品質を決める」**

という考え方を採用する。

実装は設計を形にする工程であり、品質は設計段階で決まる。

また、

**「AIを活用しながらも、人が理解し、人が判断し、人が品質を保証する」**

ことを開発の基本原則とする。

本標準は、ポータルを構成するすべてのシステムに適用し、継続的に成長する製造プラットフォームを支える共通の開発文化とする。
