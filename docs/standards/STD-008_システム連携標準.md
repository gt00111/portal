# 1. 目的

本標準は、ポータルを構成するすべてのサブシステム間の連携方法・責務・データ共有ルールを定義することを目的とする。

各システムが独立性を維持しながらも、必要な情報を適切に共有し、ポータル全体として一つの製造プラットフォームとして機能することを目指す。

---

# 2. 基本方針

ポータルでは以下の連携方針を採用する。

- 各システムは独立した責務を持つ。
    
- 必要なデータのみ連携する。
    
- データの重複管理は禁止する。
    
- 正本（Single Source of Truth）を必ず維持する。
    
- 他システムのデータを直接更新しない。
    
- 将来のシステム追加を考慮した疎結合設計とする。
    

---

# 3. システム全体構成

ポータルは以下のサブシステムで構成する。

```text
master.db
      │
      ▼
① 生産ボード
      │
      ▼
② 図面ライブラリ
      │
      ▼
③ 資材管理
      │
      ▼
④ 板金製造支援システム
```

各システムは独立して動作しながら、必要な情報を相互に参照する。

---

# 4. サブシステムの責務

|システム|主な責務|
|---|---|
|master.db|共通マスタ情報の管理|
|生産ボード|案件管理・工程管理・製造全体の入口|
|図面ライブラリ|客先図面・自社図面・Rev管理|
|資材管理|BOM・部品構成・設計変更比較|
|板金製造支援システム|加工条件・曲げ順・シミュレーション・技術ノート|

各システムは、自身の責務以外のデータを管理しない。

---

# 5. 業務データの流れ

ポータルでは案件を起点として業務が進行する。

**FLOW-001 業務データフロー**

```text
案件登録
      │
      ▼
図面登録
      │
      ▼
部品構成（BOM）
      │
      ▼
加工条件・シミュレーション
      │
      ▼
製造
      │
      ▼
加工履歴・技術ノート
```

各サブシステムは、この業務フローを前提として設計する。

---

# 6. データ連携ルール

データ連携は以下を原則とする。

- 正本システムから取得する。
    
- 必要最小限の情報のみ連携する。
    
- 他システムのデータを書き換えない。
    
- キャッシュを持つ場合も正本を変更しない。
    

システム間の整合性を維持することを最優先とする。

---

# 7. システム間連携

サブシステム間の連携は、業務サービスを経由して行う。

**FIG-001 システム連携イメージ**

```text
UI
 │
 ▼
Service
 │
 ▼
Repository
 │
 ▼
対象システム
```

直接データベースへアクセスして他システムを更新する設計は禁止する。

---

# 8. 更新通知

データ更新時は、必要に応じて関連システムへ通知できる構造とする。

例

```text
図面Rev更新
      │
      ▼
図面ライブラリ
      │
      ▼
板金製造支援システム
      │
      ▼
最新版図面を参照
```

通知方式は将来の拡張を考慮し、疎結合で設計する。

---

# 9. 新規サブシステム追加

新しいサブシステムを追加する場合は、以下を必ず定義する。

- システムの責務
    
- 正本となるデータ
    
- 他システムとの連携内容
    
- データ取得方法
    
- 更新通知の有無
    

既存システムの責務を侵害しないことを原則とする。

---

# 10. 連携時の禁止事項

以下は禁止する。

- 他システムのデータベースを直接更新する。
    
- 同じデータを複数システムで管理する。
    
- 責務を持たないデータを保持する。
    
- システム間で循環依存を作る。
    
- 一時的な都合で責務を曖昧にする。

---

# 12. 設計原則

本ポータルでは、

**「サブシステムは独立しているが、孤立してはならない。」**

という考え方を採用する。

各サブシステムは明確な責務を持ち、それぞれが専門性を発揮しながら連携することで、製造業務全体を支える一つのプラットフォームを構成する。

システム連携の目的は、機能を増やすことではなく、利用者が必要な情報を必要なタイミングで迷わず利用できる環境を実現することである。

本標準は、現在および将来追加されるすべてのサブシステムに適用する。
