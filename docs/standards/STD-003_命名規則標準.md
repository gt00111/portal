# 1. 目的

本標準は、ポータルを構成するすべてのシステムで使用する命名規則を統一し、可読性・保守性・再利用性を向上させることを目的とする。

命名規則を統一することで、

- 開発者が理解しやすいコード
    
- AIが生成しやすいコード
    
- 保守しやすいシステム
    

を実現する。

---

# 2. 基本方針

ポータルでは以下の命名方針を採用する。

- ソースコードは英語で命名する。
    
- データベースは英語で命名する。
    
- ファイル名は英語で命名する。
    
- クラス名・型名・関数名は英語で命名する。
    
- UI表示・画面タイトルは日本語とする。
    
- コメント・設計書・要件定義は日本語で記述する。
    

---

# 3. 命名ルール

## 3.1 データベース

テーブル・カラムは **snake_case** を採用する。

### 例

```text
project_id
drawing_id
part_number
customer_id
machine_id
tool_id
created_at
updated_at
created_by
updated_by
is_active
```

---

## 3.2 TypeScript

### クラス

**PascalCase**

```text
DrawingRepository
SimulationService
PartSearchHandler
MasterRepository
```

---

### Interface

先頭に **I** は付けない。

```text
Part
SimulationResult
DrawingFile
```

---

### Type

```text
ProcessCondition
ToolSelection
SimulationOption
```

---

### Enum

```text
MachineType
ToolCategory
SimulationStatus
```

---

### 関数

**camelCase**

```text
getLatestDrawing()

searchPart()

calculateProcessScore()

generateBendSequence()
```

---

### 変数

**camelCase**

```text
partNumber

drawingId

toolList

processScore
```

---

### 定数

**UPPER_SNAKE_CASE**

```text
MAX_HISTORY_COUNT

DEFAULT_SCORE

DEFAULT_MACHINE
```

# 4. Repository命名

Repositoryは

**〇〇Repository**

で統一する。

### 例

```text
DrawingRepository

MasterRepository

ProcessHistoryRepository

SimulationRepository
```

Repositoryはデータアクセスのみを担当する。

---

# 5. Service命名

Serviceは

**〇〇Service**

で統一する。

### 例

```text

TechnicalNoteService
```

Serviceは業務処理のみを担当する。

# 6. Handler命名

# 12. ドキュメントID命名

設計書・要件定義では以下のID体系を使用する。

|接頭辞|用途|
|---|---|
|STD|標準設計書|
|FIG|図|
|TBL|表|
|FLOW|処理フロー|
|DB|テーブル|
|SCR|画面|
|API|API仕様|
|REQ|要件番号|

### 例

```text
STD-001

FIG-003

TBL-005

FLOW-002

DB-001

SCR-001
```

---

# 13. コメント

コメントは日本語で記述する。

### 例

```ts
// 図面ライブラリから最新版図面を取得する
```

コメントは

- 処理の目的
    
- 判断理由
    
- 注意事項
    

を記述し、コードを説明するだけのコメントは避ける。

---

# 14. 禁止事項

以下の命名は禁止する。

### 意味が曖昧な名前

```text
data

info

temp

test

value
```

---

### 一文字変数

```text
a

b

x

y
```

※ 数学的な計算やループカウンタなど、限定的な用途を除く。

---

### 略語の乱用

```text
partNo

cust

mach

toolFlg
```

正式名称を使用する。

---

### 同じ意味で複数の表現

禁止例

```text
partNo

part_number

PartNumber

partnumber
```

正しい命名

```text
part_number
```

---

# 15. 設計原則

命名は「短さ」よりも「分かりやすさ」を優先する。

名前だけで役割が理解できることを目標とする。

ポータル全体で命名を統一することで、

- 開発効率の向上
    
- AIコード生成の品質向上
    
- 保守性の向上
    
- 新規開発者の理解促進
    

を実現する。

本標準は、ポータルを構成するすべてのシステムに適用する。
