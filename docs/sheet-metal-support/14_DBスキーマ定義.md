# 板金製造支援システム DBスキーマ定義

本書は `09_データアーキテクチャ設計.md` のデータ辞書（TBL-002）・テーブル一覧（TBL-003）を、実装可能な DDL レベルに具体化したものである。対象 DB は板金製造支援システム専用のサテライト DB **`sheet-metal-support.db`**。

---

# 1. 方針

- DB は中央ポータル DB に **隣接して自動オープン** する（`drawing-library.db` と同方式：`drawingLibraryConnection.ts` を踏襲）。
- **図面情報・マスタ情報は保持しない**（図面ライブラリ / master.db を参照）。本 DB は加工条件・シミュレーション・技術ノート・加工履歴・更新履歴のみを正本管理する。
- 全テーブルに **共通カラム**（STD-002）を採用する。
- **論理削除**（`is_active`）を採用し、原則物理削除しない。更新履歴は削除不可。
- 命名は snake_case（STD-003）。他システム参照 ID は統一識別子（`part_number` / `drawing_id` / `customer_id` / `model_id` / `tool_id` / `machine_id` / `user_id` / `revision`）を用いる。
- クロス DB の外部キーは張らない（DB を跨ぐため）。参照整合はアプリ層（Service/Repository）で担保する。

---

# 2. 共通カラム（全テーブル）

| カラム | 型 | 説明 |
|---|---|---|
| `id` | INTEGER PRIMARY KEY AUTOINCREMENT | 主キー |
| `created_at` | DATETIME DEFAULT CURRENT_TIMESTAMP | 作成日時 |
| `updated_at` | DATETIME DEFAULT CURRENT_TIMESTAMP | 更新日時 |
| `created_by` | INTEGER | 作成ユーザー（`m_user_names.id` を参照。FK は張らない） |
| `updated_by` | INTEGER | 更新ユーザー |
| `is_active` | INTEGER NOT NULL DEFAULT 1 | 有効フラグ（論理削除） |

※ `revision_histories` は監査目的のため `is_active` を持たず削除不可とする。

---

# 3. テーブル一覧（TBL-003 対応）

| テーブルID | 物理名 | 役割 | Phase |
|---|---|---|---|
| DB-001 | `process_conditions` | 加工条件（品番の加工条件本体） | 2 |
| DB-002 | `simulations` | シミュレーション設定 | 3 |
| DB-003 | `simulation_results` | シミュレーション結果 | 4 |
| DB-004 | `technical_notes` | 技術ノート | 2 |

# 4. DDL

## DB-001 `process_conditions`（加工条件）

```sql
CREATE TABLE IF NOT EXISTS process_conditions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  part_number TEXT NOT NULL,            -- 品番（図番と同一）。図面ライブラリを参照するキー
  drawing_id INTEGER,                   -- 図面ライブラリの図面ID（参照時点のスナップショット）
  customer_id INTEGER,                  -- master.db 客先ID
  model_id INTEGER,                     -- master.db 機種ID
  revision TEXT,                        -- 参照した図面Rev
  material TEXT,                        -- 材質
  thickness REAL,                       -- 板厚(mm)
  process_condition TEXT,               -- 加工条件詳細(JSON)
  process_score INTEGER,                -- 加工性評価(0-100)
  work_direction TEXT,                  -- ワーク向き
  note TEXT,                            -- 注意事項
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  created_by INTEGER,
  updated_by INTEGER,
  is_active INTEGER NOT NULL DEFAULT 1
);

CREATE INDEX IF NOT EXISTS idx_process_conditions_part
  ON process_conditions (part_number);
```

### 曲げ順の保持（`process_condition_bends`）

曲げ順・使用金型・バックゲージは 1 加工条件に対し複数（曲げステップ数分）持つため、子テーブルで管理する。

```sql
CREATE TABLE IF NOT EXISTS process_condition_bends (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  process_condition_id INTEGER NOT NULL REFERENCES process_conditions(id) ON DELETE CASCADE,
  bend_sequence INTEGER NOT NULL,       -- 曲げ順番号(1,2,3...)
  upper_tool_id INTEGER,                -- master.db 上型ID
  lower_tool_id INTEGER,                -- master.db 下型ID
  machine_id INTEGER,                   -- master.db 機械ID
  back_gauge REAL,                      -- バックゲージ位置(mm)
  angle REAL,                           -- 曲げ角度(度)
  bend_radius REAL,                     -- 曲げR(mm)
  note TEXT,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  created_by INTEGER,
  updated_by INTEGER,
  is_active INTEGER NOT NULL DEFAULT 1
);

CREATE INDEX IF NOT EXISTS idx_pc_bends_parent
  ON process_condition_bends (process_condition_id, bend_sequence);
```

## DB-002 `simulations`（シミュレーション設定）

```sql
CREATE TABLE IF NOT EXISTS simulations (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  part_number TEXT NOT NULL,
  model_file_path TEXT,                 -- STEP等3Dモデルの相対パス
  status TEXT DEFAULT 'draft',          -- draft / done
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  created_by INTEGER,
  updated_by INTEGER,
  is_active INTEGER NOT NULL DEFAULT 1
);

CREATE INDEX IF NOT EXISTS idx_simulations_part
  ON simulations (part_number);
```

## DB-003 `simulation_results`（シミュレーション結果）

判断エンジンの出力（STD-009：結果＋点数＋理由＋改善案）を保持する。レポートは保持せず、必要時に本データから帳票生成する（`11_加工判断エンジン設計.md`）。

```sql
CREATE TABLE IF NOT EXISTS simulation_results (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  simulation_id INTEGER NOT NULL REFERENCES simulations(id) ON DELETE CASCADE,
  judgement TEXT,                       -- OK / 注意 / NG
  process_score INTEGER,                -- 加工性評価(0-100)
  interference_result TEXT,             -- 干渉判定結果(JSON)
  reason TEXT,                          -- 判断理由
  recommendations TEXT,                 -- 改善案(JSON配列、推奨順)
  result_detail TEXT,                   -- 詳細ログ(JSON)
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  created_by INTEGER,
  updated_by INTEGER,
  is_active INTEGER NOT NULL DEFAULT 1
);

CREATE INDEX IF NOT EXISTS idx_sim_results_sim
  ON simulation_results (simulation_id);
```

## DB-004 `technical_notes`（技術ノート）

```sql
CREATE TABLE IF NOT EXISTS technical_notes (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  part_number TEXT NOT NULL,
  note_type TEXT,                       -- 改善案 / 設計メモ / 現場メモ / 注意事項
  body TEXT NOT NULL,                   -- 本文
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  created_by INTEGER,
  updated_by INTEGER,
  is_active INTEGER NOT NULL DEFAULT 1
);

CREATE INDEX IF NOT EXISTS idx_technical_notes_part
  ON technical_notes (part_number);
```

## DB-005 `process_histories`（加工履歴）

テスト加工専用機能は設けず、通常の加工履歴として本テーブルで管理する（`06_機能要件.md`）。

```sql
CREATE TABLE IF NOT EXISTS process_histories (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  part_number TEXT NOT NULL,
  processed_at DATE,                    -- 加工日
  machine_id INTEGER,                   -- 使用機械
  is_test INTEGER NOT NULL DEFAULT 0,   -- テスト加工フラグ
  comment TEXT,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  created_by INTEGER,
  updated_by INTEGER,
  is_active INTEGER NOT NULL DEFAULT 1
);

CREATE INDEX IF NOT EXISTS idx_process_histories_part
  ON process_histories (part_number);
```

## DB-006 `revision_histories`（更新履歴・監査ログ）

`07_非機能要件.md` §更新履歴に基づく。**削除不可**（`is_active` を持たない）。曲げ順・金型・バックゲージ・ワーク向き・注意事項・加工条件の変更を記録する。

```sql
CREATE TABLE IF NOT EXISTS revision_histories (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  target_table TEXT NOT NULL,           -- 変更対象テーブル
  target_id INTEGER NOT NULL,           -- 変更対象レコードID
  part_number TEXT,                     -- 参照用
  field_name TEXT NOT NULL,             -- 変更フィールド
  old_value TEXT,                       -- 変更前
  new_value TEXT,                       -- 変更後
  changed_by INTEGER,                   -- 更新者(user_id)
  changed_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_revision_histories_target
  ON revision_histories (target_table, target_id);
```

# 5. 参照する外部データ（保持しない）

| データ | 参照先 DB | 取得方法 |
|---|---|---|
| 図面 PDF・図番・品番・Rev・`drawing_id` | `drawing-library.db` | Drawing Repository（read-only、`改良要件定義.md` REQ-DL-002） |
| 客先・機種・金型（上下型）・機械・ユーザー | 中央ポータル DB（master系） | Master Repository（read-only） |
| ログインユーザー・権限 | ポータルセッション | Portal Session |

# 6. ER 図（実装版）

```text
process_conditions (DB-001)
  ├──< process_condition_bends
simulations (DB-002)
  └──< simulation_results (DB-003)
technical_notes (DB-004)
process_histories (DB-005)
revision_histories (DB-006)   ※各テーブルの変更を横断記録

（外部参照・保持しない）
drawing-library.db : Part / Drawing
master系           : Customer / Model / Tool / Machine / User
```

すべて `part_number` を軸に紐付く（品番中心設計）。
