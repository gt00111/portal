# Phase 3：M-BEND金型形状・取付基準管理

## 実装範囲

M-BEND専用マスターの上型・下型・ホルダー／中間板に、STEP形状と取付基準を登録する。
機械本体の形状、モデル面クリックによる基準選択、ホルダー積層、実形状による干渉判定は次段階とする。
ポータル共通マスターへの新規項目追加は行わない。

## 使用方法

1. ポータルを再起動してM-BENDを開く。
2. 上型・下型・ホルダーのいずれかを選び、「基本情報」で金型を登録する。
3. 「STEP・取付基準」で対象金型を選ぶ。
4. 「STEPを選択して登録」からSTEP/STPを指定する（50MB以下）。
5. 元モデルの基準点・基準面・回転角度・位置補正を入力する。
6. 「3Dに反映」で確認し、「基準位置を保存」で確定する。
7. 「CAMファイル出力」で連携JSONに出力する。

選択金型の変更や基本情報への切り替え前に保存すること。3Dに反映しただけでは保存されない。

## 座標規約（形状連携schemaVersion 1）

- 長さ：mm。既存OCCT STEPインポートのmm出力を使用。
- 右手系：X＝金型長さ、Y＝バックゲージ側、Z＝上方向。
- `anchor`：元STEP座標の上型先端中心、下型V溝中心、ホルダー中心。
- `mountPoint`：元STEP座標の取付面上の一点。下型では上面上の一点。
- `mountNormal`：同じ元座標での面法線（非ゼロ）。平面は点と法線の組で表す。
- `rotationDeg`：固定軸X→Y→Zの順の回転（度）。
- `offset`：回転後の座標での追加移動量（mm）。

変換式：`p_tool = offset + Rz * Ry * Rx * (p_source - anchor)`。
`sourceToToolMatrix` はこの式を列優先の4×4行列として出力する。
面法線には回転だけを適用し正規化する。面基準は配置を自動決定せず、後段CAMのためのメタデータとして扱う。

プレビューの赤・緑・青はそれぞれ配置先X・Y・Z軸、紫の矢印は変換後の基準面法線。
ビューアの自動画面フィットは表示用で、保存・出力座標には影響しない。
金型表示では板金ワーク用の曲げ箇所検出を実行しない。

## DBとファイル

- `m-bend.db` スキーマv2。v1からの更新は既存マスターを維持しトランザクションで実行。
- `tool_geometry` は上型・下型・ホルダーのうち必ず一つを外部キーで参照。
- 保存内容：元ファイル名、相対パス、SHA-256、取付設定JSON、更新番号、作成・更新日時。
- 保存先：DBと同じディレクトリの `m-bend-assets/models/<SHA-256>.step`。
- ファイルはコピーし、原本を移動・削除しない。
- 異なる形状へ差し替えると取付設定を初期化。同一SHA-256なら保存済み設定を保持。
- 旧モデル実ファイルは残す。旧設定を切り替える履歴UIはこのPhaseには含まない。
- 更新番号が異なる保存は拒否し、他の操作による更新を上書きしない。
- DBと `m-bend-assets` をセットでバックアップする。

## CAM出力

既存の上型・下型JSONにオプションの `geometry` を追加し、上型・下型・ホルダーをまとめた `tools/tool-geometry.json` を追加。
既存の寸法値や金型IDは変更しない。モデル未登録の金型は `geometry: null`。
STEPのパスは同一端末／共有ストレージで参照する絶対パスとして出力され、ファイル一式の可搬パッケージではない。

**M-BEND本体の実モデル読込・干渉判定は未実装。** 今回の形状連携は準備データであり、`simulationReady: false` を明示する。
M-BEND本体がこの規約を読み取り、取付位置と単位を照合するまでは従来のシミュレーション形状のまま。

## 検証

- TypeScript型チェック、本番ビルド。
- `scripts/test-mbend-geometry.cjs`：メモリDBと一時フォルダーで実行。
- v1→v2更新、更新の再実行、前方バージョン拒否、外部キー整合性。
- 金型種別間の分離、不正座標・法線の拒否、行列の基準点移動と回転。
- STEP登録・読み出し・出力、同一ファイル再登録、差し替え時の初期化と旧実ファイル保持。
- 競合更新拒否、不正STEP拒否。

実機確認：既知の寸法・向きを持つSTEPで、先端／V中心、取付面法線、90度回転、XYZ補正、保存・再起動後の復元を確認する。
自動テストはファイル管理用の小さなSTEPヘッダーを使用し、実CAD形状の描画成立は検証しない。
