# 1. 目的

本章では、板金製造支援システムのシステム構成・各コンポーネントの責務・データの流れ・処理の流れを定義する。

本システムは単なるCRUDアプリケーションではなく、

**「設計と現場をつなぐ判断支援プラットフォーム」**

として構築する。

そのため、画面・業務処理・判断処理・データ管理を明確に分離し、保守性・拡張性・再利用性を高める。

---

# 2. 設計方針

本システムは以下の設計方針を採用する。

- 責務を明確に分離する。
    
- UIは表示・入力に専念する。
    
- 業務処理はApplication Serviceが担当する。
    
- 判断処理は判断エンジンが担当する。
    
- 技術情報はナレッジベースで管理する。
    
- データアクセスはRepository経由のみとする。
    
- Repository以外からDBへ直接アクセスしない。
    
- 将来AIへ置き換えられる構造を前提とする。

# 5. Application Service

Application Serviceは、本システムの業務処理を統括する。

Repositoryを直接呼び出すのではなく、

必要に応じて

- 判断エンジン
    
- ナレッジベース
    
- Repository
    

を組み合わせて処理を実行する。

# 11. AI拡張方針

本システムはAIありきでは設計しない。

判断エンジンはルールベースで完成させる。

将来的にAIを導入する場合は、

Recommendation EngineをAIへ置き換えることで対応する。

そのため、AIは判断エンジンの一部機能として位置付ける。

---

# 12. 設計原則

本システムは以下の責務分離を基本とする。

- UIは表示のみ。
    
- Application Serviceは業務処理のみ。
    
- 判断エンジンは加工判断のみ。
    
- ナレッジベースは知識管理のみ。
    
- Repositoryはデータアクセスのみ。
    
- Databaseはデータ保存のみ。
    

各コンポーネントは単一責務（Single Responsibility Principle）を遵守し、変更の影響範囲を最小限に抑える。

本章で定義したシステムアーキテクチャを基盤として、11章「判断エンジン設計」で各判断ロジックの詳細を設計する。
