# 1. 目的

本章では、板金製造支援システムで扱うデータの管理方針・責務・流れ・構造を定義する。

本システムは単独でデータを管理するのではなく、ポータルアプリ全体のデータアーキテクチャの一部として設計する。

データの重複管理を避け、それぞれのシステムが責任を持つデータ（Single Source of Truth）を明確にする。

---

# 2. データ管理方針

本システムでは以下の基本方針を採用する。

- データは重複管理しない。
    
- Single Source of Truth（正本管理）を徹底する。
    
- 他システムが管理するデータは参照のみとする。
    
- 板金製造支援システム固有のデータのみ保持する。
    
- データの責務を明確に分離する。
    
- 将来のシステム拡張を考慮した設計とする。

## システムの役割

### master.db

会社共通のマスタデータを管理する。

### 生産ボード

案件情報の正本となる。

### 図面ライブラリ

図面・PDF・Rev情報の正本となる。

### 資材管理

BOM・部品構成・部品比較情報の正本となる。

### 板金製造支援システム

加工知識・加工条件・シミュレーション結果を管理する。

# 10. データ責務の原則

- 図面は図面ライブラリが正本とする。
    
- 案件は生産ボードが正本とする。
    
- BOMは資材管理が正本とする。
    
- マスタ情報は master.db が正本とする。
    
- 加工条件・シミュレーション結果・技術ノート・加工履歴は板金製造支援システムが正本とする。
    
- 各データは一つのシステムのみが正本となり、他システムは参照する。

# 11. 設計方針

本システムはポータル全体の製造プラットフォームを構成する一要素として設計する。

設計方針は以下とする。

- Single Source of Truth を徹底する。
    
- データの重複を防ぐ。
    
- システム間の責務を明確に分離する。
    
- Repositoryを介して他システムのデータを取得する。
    
- 保守性・拡張性を重視する。
    
- 将来のAI・判断エンジン機能拡張を考慮した構成とする。
    

本章で定義したデータアーキテクチャを、10章「システムアーキテクチャ設計」の前提条件とする。
