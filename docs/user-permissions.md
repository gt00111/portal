# ユーザー権限メモ（フェーズ 4-A）

運用・設定時の参照用。**2026-05-19 時点のコード挙動**に基づく。設計の詳細は [task-progress.md](./task-progress.md) の「フェーズ 4-A」を参照。

---

## 1. 権限の2層 + グループ

| 層 | 設定場所 | 何を決めるか |
|----|----------|--------------|
| **ポータル権限** | 管理 › 操作者（`app_operators.role`） | DB パス・会社情報・操作者・**マスタ編集**・ユーザー権限画面 |
| **アプリ権限** | マスタ › **ユーザー権限**（`m_user_app_grants`） | 各内蔵アプリの admin / editor / viewer（工程管理のみ **工程表示** も） |
| **グループ役割** | 同上（`m_user_group_memberships`） | 所属グループ（0〜1）と **一般 / グループ管理者** |

- ログイン名（`app_operators.username`）とマスタユーザー名（`m_user_names.name`）は **同一**。
- アプリ権限の強さ: **viewer < editor < admin**（`src/shared/auth.ts`）。
- **grant 未設定**（マスタでアプリを付けていない）→ そのアプリの `canAppView` / `canAppWrite` は **false**。

---

## 2. ポータル権限（操作者）

| ポータル role | できること | できないこと |
|---------------|------------|--------------|
| **admin** | 管理メニュー（設定・操作者・マスタ）、中央 DB / 会社情報、マスタ CRUD、SKU、**ユーザー権限**編集 | 業務アプリの操作権は **別途** アプリ grant が必要 |
| **editor / viewer** | ログイン、ホームからアプリ起動、付与されたアプリ権限に従う業務 | `/admin` 配下、マスタ編集、操作者管理 |

---

## 3. アプリ別：できること / できないこと

### 3.1 マスターデータ

> マスタ UI に `master-database` の grant 項目はあるが、**IPC はポータル admin のみ**を見る（grant は現状未使用）。

| 条件 | できること | できないこと |
|------|------------|--------------|
| ポータル **admin** | 全マスタ CRUD、SKU、ユーザー権限 | — |
| それ以外 | — | 管理メニューからマスタに入れない |

---

### 3.2 生産ボード（`seisan-board`）

UI は grant を次のように解釈: **admin → 承認者（approver）**、editor → 編集者、viewer → 閲覧のみ。

| grant | UI 上できること | UI 上できないこと |
|-------|-----------------|-------------------|
| **viewer** | 案件・タスク・ガント・ダッシュボードの閲覧、添付の一覧・プレビュー・保存 | 案件/タスクの作成・編集、ガント編集、CSV 取込、設定変更 |
| **editor** | viewer + 案件・タスク・ガントの編集 | 案件の**承認** |
| **admin** | editor + 案件の**承認** | — |

**IPC の注意（2026-05 時点）**  
多くの生産ボード IPC（案件 create/update 等）は **ログインのみ**チェック。grant は UI が主。厳密に grant を見ている例: `seisan-file:setObsolete`（editor 以上）など一部。

---

### 3.3 図面ライブラリ（`drawing-library`）

IPC で grant をチェック（editor 以上 = 書込）。

| grant | できること | できないこと |
|-------|------------|--------------|
| **未設定 / viewer** | 顧客図面・自社図面の一覧・閲覧、PDF 比較、ファイル読取・ダウンロード | 自社図面の登録・更新・削除、eDrawings/コメントの追加・削除、obsolete 更新 |
| **editor / admin** | 上記 + 自社図面 CRUD、添付・コメントの追加・削除 | （現状 admin 専用の追加機能はほぼなし） |

---

### 3.4 工程管理（`process-management`）

**工程表示**（SolidWorks / CADMAC / 両方）は grant の `processView` で、表示される工程の範囲が変わる（権限 tier とは別）。

| grant | できること | できないこと |
|-------|------------|--------------|
| **未設定** | — | ボード・マイタスク等（IPC 拒否） |
| **viewer** | ボード・マイタスク閲覧、タスクの**開始・完了**、**自分が assignee** の進捗％・メモ、案件詳細閲覧 | タスク/案件の作成・編集・削除、完了取り消し、他人の進捗メモ編集 |
| **editor** | viewer + タスク/案件の CRUD、ステータス変更 | 完了取り消し、他人の進捗メモ（assignee または工程 admin のみ） |
| **admin** | editor + **完了取り消し**、**任意 assignee** の進捗％・メモ | 完了通知の自動送信先になること（別途グループ管理者） |

**グループ `group_admin`（アプリ権限とは別）**

| 条件 | 追加でできること |
|------|------------------|
| マスタで **グループ管理者** + 工程管理 **viewer 以上** | ヘッダの**完了通知ベル**、自グループ案件のタスク完了時の**インナー通知**受信 |

完了通知の宛先は **当該案件グループの group_admin のみ**（完了者除外）。portal admin 全員には送らない。

---

### 3.5 PixoConverter（`pixo-converter`）

| 状態 | できること |
|------|------------|
| **ログイン済み** | PDF/TIFF/画像変換、連結・ページ編集など **全機能** |

> マスタに grant 項目はあるが、IPC は **ログインのみ**（grant は現状未使用）。

## 4. 設定の目安（運用例）

| 役割 | ポータル | アプリ grant | グループ |
|------|----------|--------------|----------|
| 現場（作業のみ） | editor 等 | 各アプリ **viewer**（工程は開始・完了可） | **一般** |
| リーダー（入力） | editor | 担当アプリ **editor** | 一般 |
| アプリ責任者 | editor | 担当アプリ **admin** | 任意 |
| グループ長（完了報告受け） | editor | 工程管理 **viewer+** | **グループ管理者** |
| IT / マスタ管理 | **admin** | 必要に応じて付与 | 任意 |

新規操作者作成時は全アプリ **viewer** で seed される。**マスタ › ユーザー権限**で本番の grant を設定すること。
